# Lanilot Dispatch MVP

Локальный рабочий кабинет диспетчера: поиск грузов, расчёт маржи, предложения брокерам и управление рейсами.

## Запуск

Требуется Node.js 22.13+ (используется встроенный `node:sqlite`).

```sh
npm install
npm run dev
```

Интерфейс: http://127.0.0.1:5173. API: http://127.0.0.1:3001.

```sh
npm test
npm run build
npm start
```

После сборки `npm start` обслуживает интерфейс и API на http://127.0.0.1:3001.

## Возможности

- 14 тестовых грузов; фильтры по направлению, технике, дате, источнику, ставке на общую милю, пустому пробегу и факторингу.
- Карточка груза с изменяемой ставкой, топливом, расходом, оплатой водителя, дорогами, факторингом и прочими расходами.
- Редактируемое предложение на английском; копирование и скачивание текста.
- Статусы предложения: черновик → ожидание → подтверждение/отказ; отмена активных черновиков и запросов.
- Создание рейса после отметки подтверждения брокера; защита от дублей и пересечений назначений одной машины.
- Статусы рейса: запланирован → в пути → доставлен → завершён.
- Сохранение предложений, условий расчёта и рейсов в `data/lanilot.sqlite`.
- Компактный Load Board со строкой фильтров, источниками, избранным и пагинацией; карточка открывается справа на всю высоту, максимум на 40% ширины. На телефоне — полноэкранно с кнопкой «Назад».
- Обзор с показателями из сохранённых данных, списком рейсов и предложениями, требующими внимания.
- Недельный Dispatch Planner с навигацией по датам, фильтрами статусов и переключением на доску.
- На мобильных экранах грузы представлены карточками, фильтры свёрнуты по умолчанию.
- Клавиатурная навигация, Escape и удержание фокуса в диалогах. Избранное сохраняется в браузере.

## Границы MVP

Это однопользовательская локальная версия без авторизации и реальных интеграций. DAT, Truckstop, почта, GPS и проверки факторинга не подключены. Любые статусы брокера и подтверждения — демонстрационные. Ни одно письмо не отправляется. Маржа учитывает только указанные переменные расходы, без налогов и постоянных затрат. Все операции в USD, mi, gal, ft и lbs.

Сервер слушает только loopback. Для многопользовательского размещения нужны авторизация, изоляция организаций, журнал действий и подключение источников данных. Не публикуйте текущий API как общий рабочий сервис.

## Структура

- `src/main.jsx` — точка входа React.
- `src/App.jsx` — оболочка, состояние и диалоги предложений.
- `src/workspace.jsx` — Load Board, обзор, предложения и Dispatch Planner.
- `src/ui.js` — форматирование и подписи статусов.
- `src/styles.css` — компактная адаптивная дизайн-система.
- `server/app.js` — API и SQLite.
- `server/domain.js` — расчёты и переходы статусов.
- `server/seed.js` — тестовые грузы; даты задаются при первом создании базы.
- `tests/` — интеграционные проверки и расчёт экономики.
- `research/` — исходный анализ Numeo.

## Проверенный сценарий

Поиск Chicago → карточка Chicago–Dallas → ставка $2,600 → черновик → демо-запрос → демо-подтверждение брокера → рейс DEMO-101 → последовательное изменение статусов. В локальной базе может оставаться этот явно обозначенный тестовый рейс после браузерной проверки.


## Отзывы логиста (октябрь 2026)

- **Прибыль вместо маржи.** Оплата водителя по умолчанию $0.75/mi (Настройки); у каждого водителя в Автопарке можно задать свою ставку (например $0.80/mi) — она используется в рейсах, планировщике, обзоре и финансах. Считается на все мили, включая DH.
- **Источник ставки.** Площадка-источник (DAT, Truckstop…) показана рядом со ставкой и RPM в таблице, карточках и карточке груза; в Load Radar — колонка «Источник» (где радар нашёл груз).
- **Экспорт.** Кнопка «Экспорт» на Load Board: история рейсов для налогов (фактические суммы из Финансов, период по дате доставки, итоги) или текущие грузы — в Excel (.xlsx) или CSV. Без внешних библиотек (`src/export.js`).
- **DNU и FreightGuard.** Реестр брокеров (`server/brokers.js`): предупреждения в Load Board, карточке груза, Load Radar и подборках ИИ-помощника.
- **Проверка брокеров/перевозчиков.** Страница проверки через факторинговую компанию по названию, MC или DOT; вердикт «можно работать / осторожно / не работать», ведение своего DNU-списка. Сейчас — демо-провайдер `Demo Factoring`.
- **Выделенные линии.** Контрактные линии: брокер, ставка, дни недели, срок; рейсы на неделе и совпадения на доске (`server/lanes.js`).
- **Карта автопарка (ELD).** Позиции машин, статусы, HOS, маршрут рейса; обновление каждые 15 секунд. Сейчас позиции симулируются по расписанию рейса (`server/eld.js`); для реальных данных нужен API Samsara или Motive.

## Языки интерфейса

English (по умолчанию), Español, Français, Italiano, Русский, Oʻzbekcha — переключатель в шапке страницы, выбор сохраняется в браузере, ссылка `?lang=es` открывает нужный язык. Ключи словаря — русские строки, обёрнутые в `__()` (`src/i18n.js`); переводы — `src/locales/*.json`. Данные сервера (демо-тексты, статусы, ошибки) переводятся на клиенте по точному совпадению, введённый пользователем текст не меняется.

## Seed по умолчанию

При каждом запуске `npm run dev` или `npm start` автоматически выполняется добавочный seed. В новой базе: 14 грузов, 10 предложений с разными статусами, 6 рейсов, 8 водителей, 8 машин, 30 сообщений в 14 переписках, 14 брокеров и перевозчиков (DNU/FreightGuard — только у вымышленных демо-компаний) и 3 выделенные линии. Существующие предложения и рейсы могут увеличивать эти числа. Стабильные ID исключают дубли; изменения пользователя, отмены и прочитанные сообщения сохраняются. Недостающие базовые грузы добавляются обратно.

```sh
npm run seed
```

Для каждой новой функции добавляйте соответствующие демонстрационные сценарии в `server/demo-seed.js`. Тесты изолированных сценариев могут использовать `createApp(path, {seedDemo:false})`.

## Карта и переписка

- Карта в карточке: Leaflet, подложка OpenStreetMap, метки A/B, дорожный маршрут, масштабирование, возврат к маршруту и открытие в OSM.
- Для всех 12 грузов геометрия дороги закеширована в `server/routes.json`. Обновление: `npm run routes:cache -- --refresh` (нужен интернет).
- Маршрут строится между центрами городов с профилем автомобильного движения OSRM. Он не проверяет ограничения грузовиков, HOS, реальные адреса, трафик или точное время прибытия. Пробег на карте отделён от пробега объявления, используемого в калькуляторе. При отсутствии геометрии показывается явно обозначенная прямая линия. Подложка карты требует интернета.
- Вкладка «Переписка» доступна в карточке и из верхнего меню. В ней история, переключение между грузами, быстрые ответы, черновик в браузере, локальная отправка и явная симуляция входящего сообщения.
- Переписка сохраняется в SQLite. Отправка в демо не отправляет email. Подтверждение сделки по-прежнему выполняется отдельным действием; текст входящего сообщения не меняет статус предложения автоматически.

Документация библиотек: [Leaflet](https://leafletjs.com/reference.html), [OSRM](https://project-osrm.org/docs/v5.24.0/api/).

### Создание рейса из карточки

Вкладка «Рейс» позволяет выбрать водителя и машину из демо-каталога, изменить даты погрузки и доставки и выбрать начальный статус. Без подтверждения брокера сохраняется только внутренний план; подтверждение предложения не меняется автоматически. Для подтверждённого предложения доступны все четыре начальных статуса. Повторный рейс по грузу, неверные даты и пересечения занятости водителя или машины отклоняются. Даты рейса сохраняются отдельно от объявления и используются в планировщике.

Стартовый seed добавляет шесть водителей, шесть машин и подтверждённое предложение LD-2049 без рейса. Уже существующие четыре рейса показывают разные статусы. Seed использует стабильные ID и не сбрасывает пользовательские изменения.

### Общие элементы управления

Все списки используют Vue 3 компонент `src/components/SearchDropdown.js` через React-обёртку `SearchSelect`. Он поддерживает поиск, клавиатуру, недоступные варианты, пустую выдачу, выбор внутри форм и позиционирование меню по границам экрана. Общие размеры и состояния полей/кнопок заданы в `src/controls.css`. Каталоги для проверки доступны в автоматическом seed: шесть водителей, шесть машин, техника, источники и переписки.

### Редактирование рейса

В карточке груза → «Рейс» → «Редактировать рейс» доступны водитель, машина, даты и любой корректный статус. Дропдауны поддерживают поиск и сохраняют ранее введённые назначения, даже если их нет в демо-каталоге. «Отменить изменения» возвращает сохранённые значения. Ошибки показываются в форме без потери ввода. Сохранение использует `PUT /api/trips/:id`; проверки дат и занятости выполняются до единого UPDATE, исключая сам рейс. Быстрые переходы статуса в планировщике сохраняют последовательный порядок. Для начала неподтверждённого рейса по-прежнему требуется подтверждение брокера.

Seed для редактирования: существующие четыре рейса в разных статусах, включая запланированный LD-2044, и резервные Casey Taylor / TRK-402 (Box Truck). Всего шесть водителей и шесть машин. Сохранённые назначения, даты и статусы не перезаписываются при старте.

### Отмена рейса

В карточке груза → «Рейс» → «Отменить рейс» открывается подтверждение с обязательной причиной (3–1000 символов). Действие сохраняет причину и время, освобождает машину и водителя и оставляет рейс в истории. Завершённые рейсы отменять нельзя; отменённый рейс нельзя редактировать до восстановления. Возврат из подтверждения ничего не меняет. Предложение брокеру сохраняет прежний статус; уведомления не отправляются.

`POST /api/trips/:id/cancel` принимает `{reason, confirmed:true}`. Повторный запрос не перезаписывает первоначальную причину и время. В планировщике доступны статус и фильтр «Отменён», причина в строке/карточке и отдельная колонка доски. Отменённые рейсы исключены из выручки, маржи, пробега и активных машин.

Seed по умолчанию добавляет отменённый LD-2050 с причиной и датой отмены; запланированные и активные рейсы позволяют проверить подтверждение самостоятельно. Данные добавляются по стабильным ID без перезаписи изменений.

### Восстановление отменённого рейса

В карточке отменённого рейса кнопка «Восстановить рейс» открывает подтверждение с поисковым списком нового статуса. Назначения и даты сохраняются. При восстановлении в «Запланирован» или «В пути» повторно проверяется пересечение занятости водителя и машины (включая день доставки). Статусы «Доставлен» и «Завершён» не резервируют ресурсы. До подтверждения предложения доступно только планирование. Отказ от подтверждения ничего не меняет.

`POST /api/trips/:id/restore` принимает `{status, confirmed:true}`. Восстановление доступно только отменённым рейсам. Причина и время прежней отмены сохраняются; каждое новое действие записывается в историю рейса вместе со статусом и временем. Повторный запуск seed не перезаписывает восстановленный рейс или его историю.

Стартовый seed включает свободный отменённый LD-2050 и отменённый LD-2051 с Alex Morgan / TRK-108, занятыми на LD-2046. Это позволяет проверить успешное восстановление и отказ при конфликте. Существующие пользовательские назначения остаются приоритетными.

### Настройки рабочего пространства (P0)

Верхнее меню → «Настройки»: профиль перевозчика (название, контакт, email, телефон, город и часовой пояс) и общие расходы для расчёта маржи. Поисковый Vue-дропдаун используется для часового пояса. Пример на 900 mi + 50 mi DH показывает влияние расходов до сохранения. Можно сохранить или отменить изменения.

`PUT /api/settings` атомарно сохраняет `{company,costs}` с серверной валидацией. Новая SQLite-таблица `settings` автоматически заполняется демо-профилем Lanilot Cargo и базовыми расходами из `server/settings.js`; повторный запуск не сбрасывает настройки. Изменение расходов влияет на поиск, карточки без сохранённого предложения и новые предложения/внутренние планы. Существующие предложения и рейсы сохраняют снимок своих расходов. Часовой пояс хранится в профиле; даты маршрутов не преобразуются. Подключения почты и площадок остаются отдельным этапом.

### Автопарк и водители

Раздел «Автопарк» содержит таблицы машин и водителей, поиск, фильтр доступности, создание и редактирование. Тип техники и доступность выбираются через Vue-дропдауны с поиском. Водитель: имя, телефон, город, тип техники (или любой), доступность и примечание. Машина: постоянный номер, госномер, город, тип техники, доступность и примечание. Локация задаётся вручную; GPS не подключён.

Доступность водителя: доступен / не на смене / в отпуске / неактивен. Машины: доступна / обслуживание / неактивна. Это разрешение на новые назначения; число активных рейсов показывается отдельно и не означает занятость на любую будущую дату. Создание, редактирование, начало и восстановление активного рейса проверяют доступность зарегистрированных ресурсов и пересечение дат. Недоступные варианты отмечаются в дропдаунах назначения. Совместимость техники с конкретным грузом пока проверяется диспетчером.

При активных назначениях нельзя менять доступность и тип техники. Имя водителя можно исправить: соответствующие назначения обновляются атомарно, чтобы переименование не обходило проверку занятости. Постоянный номер машины после создания неизменяем. Прежние назначения с именами вне справочника сохраняются для совместимости с ранним MVP.

API: `POST /api/drivers`, `PUT /api/drivers/:id`, `POST /api/trucks`, `PUT /api/trucks/:id`. Сервер проверяет поля и уникальность имён/номеров без учёта регистра. Startup миграция добавляет поля к существующим таблицам. Seed по умолчанию содержит по 8 записей: прежние 6 плюс Taylor Reed (отпуск), Morgan Lee (не на смене), TRK-501 (обслуживание) и TRK-502 (неактивна). Повторный seed не перезаписывает созданные и изменённые записи.

### Load Radar

Раздел Load Radar сохраняет название поиска, города отправления/назначения (или любое направление), тип техники и минимальную ставку: $ за груз либо $/mi с учётом DH. Для ввода критериев используются дропдауны с поиском. Радар можно создавать, редактировать, включать и ставить на паузу. Подбор выполняется на сервере по точным городам без радиуса; минимальная ставка включительна. Результаты отсортированы по ставке, открывают обычную карточку груза без ухода из Radar.

Выключенный радар сохраняет критерии и не показывает результаты; после включения результаты пересчитываются по текущему каталогу. Проверка выполняется при загрузке/обновлении кабинета и изменении радара. Это локальный демо-поиск: фонового мониторинга площадок, email/push-уведомлений и реального обновления грузов пока нет.

API: `POST /api/radars`, `PUT /api/radars/:id`, `PATCH /api/radars/:id` с `{enabled:boolean}`, `GET /api/radars/:id/results`. Настройки хранятся в SQLite. Seed по умолчанию включает четыре радара: Chicago / Dry Van от $2,000; Chicago / Reefer от $3.50 за общую милю; выключенный Dallas → Phoenix; активный Cargo Van без результатов. Seed не перезаписывает правки и выключенные состояния.

Шапка закреплена отдельным фиксированным слоем, а отступ страницы измеряется через ResizeObserver. Это устраняет зависимость навигации от sticky-композиции Safari и учитывает высоту мобильного меню.

### Документы рейса

Вкладка «Документы» в карточке груза принимает Rate Confirmation, BOL и POD. Доступны чек-лист полученных/недостающих документов, ручная отметка проверки диспетчером, встроенный просмотр PDF/изображений и скачивание. PDF открывается через PDF.js с масштабированием и перелистыванием страниц; модуль загружается при открытии просмотра. Есть ссылка на скачивание. Загрузка не меняет статус рейса или подтверждение брокера.

Форматы: PDF, PNG и JPEG, до 10 МБ. Файл отправляется бинарным телом на `POST /api/loads/:id/documents?kind=rc|bol|pod&filename=...&clientId=...`; имя, расширение, Content-Type и сигнатура проверяются сервером. Ключ загрузки защищает от дублирования при повторной попытке. Бинарное содержимое хранится в SQLite BLOB вместе с метаданными; `/api/state` возвращает только метаданные. Получение: `/api/documents/:id/file` (inline), `?download=1` (скачать). `PATCH /api/documents/:id` с `{reviewed:boolean}` сохраняет ручную проверку. Полная юридическая/структурная проверка содержимого и антивирусная проверка не выполняются.

Seed добавляет 9 файлов: RC для LD-2044; RC/BOL для LD-2046; RC/BOL/POD для LD-2047 и LD-2048. Учебные PDF лежат в `output/pdf/`, содержат явную отметку DEMO и не являются реальными транспортными документами. Автоматический seed сохраняет загруженные файлы и отметки проверки. Генератор fixtures: `scripts/create-document-fixtures.py` (ReportLab нужен только для повторной генерации; обычный запуск использует готовые PDF).

### Окно переписок

Чат открывается плавающим модальным окном с отступом 50px от границ экрана. Слева список переписок с поиском, последним сообщением и числом непрочитанных; справа сообщения и ввод. Ширина списка изменяется перетаскиванием разделителя либо клавишами стрелок/Home/End и сохраняется в браузере. Максимум - половина ширины окна (не больше половины экрана). На узком экране список переключается кнопкой «Чаты». Основной текст чёрный, вторичный контрастный. Демо-сообщения по-прежнему сохраняются локально без отправки брокеру.

### Вложения в переписке и финансы

Скрепка в чате принимает до 10 файлов за раз, каждый до 25 МБ. До отправки можно открыть превью или убрать файл. Отправка сохраняет вложения локально; каждый файл — отдельное сообщение с подписью. Изображения открываются на тёмном фоне, PDF — через PDF.js, распознаваемые аудио/видео — через браузерный плеер (поддержка кодеков зависит от браузера). Остальные документы скачиваются. HTML и неизвестные форматы не исполняются и выдаются как attachment с nosniff. Данные хранятся SQLite BLOB; повтор запроса с тем же ключом не дублирует сообщение. `/api/state` содержит только метаданные. Seed добавляет учебный PDF и изображение в переписку LD-2046.

«Финансы» доступны в навигации и карточке груза после создания рейса. Доход, топливо, водитель, дороги, факторинг и прочее учитываются вручную в USD; прибыль = доход − расходы. Полученная сумма, остаток, номер счёта, срок и статус оплаты сохраняются отдельно от статуса рейса. Просрочка вычисляется по сроку и неоплаченному остатку. Статусы выбираются через Vue-дропдаун с поиском; суммы проверяются на согласованность. Для новых рейсов сначала показан расчёт предложения, после сохранения — ручной учёт. Seed дополняет только учебные рейсы, сохраняет изменения и показывает разные состояния оплаты. Отменённые рейсы включены в сводку, поскольку отмена не обнуляет финансовые обязательства автоматически.

### Централизованные интеграции

Раздел «Интеграции» показывает общие серверные источники DAT, Truckstop, RXO и Uber Freight. Клиентские ключи и отдельные подключения пользователей не требуются. Настройки доступа задаёт оператор в окружении сервера, по шаблону `.env.example`; локальный `.env` загружается при старте API и исключён из Git. После изменений нужен перезапуск API. Токены/ключи не сохраняются в SQLite и не возвращаются в `/api/state`.

По умолчанию seed добавляет четыре явно учебных состояния: успешный DAT, ошибка Truckstop, ненастроенный RXO, выключенный Uber Freight. Seed не сбрасывает результаты проверок. Для реальной проверки оператор задаёт `LANILOT_<DAT|TRUCKSTOP|RXO|UBER>_MODE=live`, `CHECK_URL`, `TOKEN` (готовый Bearer-токен) и/или `API_KEY` (x-api-key), `ACCOUNT`, `ENVIRONMENT` и `ENABLED`. Адрес проверки должен быть выдан провайдером: авторизованный read-only GET endpoint на HTTPS-домене площадки, без query, паролей и редиректов. Частные IP блокируются, DNS/запрос ограничены по времени. Смена доступа сбрасывает ранее успешный статус до новой проверки. Демо-проверка не делает сетевых запросов.

`POST /api/integrations/:id/check` выполняет общую проверку сервера и сохраняет результат/время. HTTP 2xx подтверждает ответ настроенного API, 401/403 — отказ доступа, 429 — ограничение частоты; тексты ответов и секреты не показываются пользователям. Параллельные проверки одного источника отклоняются. Проверка доступности **не является импортом грузов**. Выдача/обновление OAuth-токенов, провайдерские поисковые коннекторы и согласование права общей выдачи данных ещё нужны для production. Скрейпинг закрытых кабинетов не реализован.

Навигация находится в обычном потоке страницы: без fixed/sticky и GPU-трансформации, которые могли приводить к обрезанию шапки Safari. При прокрутке она уходит вместе со страницей; на узких экранах пункты прокручиваются горизонтально.

### Telegram компании и ИИ-уведомления

Раздел «Telegram» подключает **бота текущей компании**, независимо от общих коннекторов DAT/Truckstop/RXO/Uber. Сохраните Bot Token из BotFather, Chat ID (число для личного чата/группы либо @имя канала), режим и критерии. Пользователь сначала должен запустить бота или добавить его в группу и разрешить отправку. «Проверить бота и чат» вызывает Telegram `getMe` и `getChat`; отдельная кнопка отправляет тест через `sendMessage`. Тест подтверждает право отправки, проверка бота сама по себе этого не гарантирует.

Токен хранится AES-256-GCM в SQLite. Ключ `data/lanilot.sqlite.telegram.key` создаётся с правами 0600 и должен резервироваться вместе с базой отдельно от публичных файлов. Сохранённый токен никогда не возвращается в браузер, пустое поле сохраняет существующий, флажок удаления очищает его. Токены и ответы Telegram не попадают в тексты ошибок. Настройки и журнал имеют `company_id`, берущийся **только из окружения сервера** `LANILOT_COMPANY_ID` (по умолчанию workspace), а не из параметров клиента. Эта версия по-прежнему однопользовательская: для нескольких компаний в одном опубликованном приложении необходимы авторизация и извлечение company_id из серверной сессии для всех данных; текущий company_id не заменяет систему прав доступа.

Для настоящего ИИ задайте на сервере `OPENAI_API_KEY` и `LANILOT_AI_MODEL` — модель Responses API с поддержкой Structured Outputs — и перезапустите сервер. Приложение отправляет только выбранные поля грузов и критерии, без токена Telegram и контактов компании. ИИ возвращает до 5 ID, оценку и объяснение; ответ проверяется по JSON-схеме и списку переданных грузов. При отказе, таймауте, незавершённом ответе или неизвестном ID рекомендации не отправляются. Экономика вычисляется сервером, а не моделью. До ИИ применяются точный маршрут, тип техники, минимальные ставка/прибыль и календарная дата погрузки. Сейчас каталог учебный, что указано в сообщениях.

Включённые уведомления проверяются серверным worker раз в минуту с учётом выбранного периода 5/15/30/60 минут и тихих часов в часовом поясе профиля. Нужен работающий процесс `server/index.js`; браузер можно закрыть. Ручной запуск игнорирует тихие часы/период, но требует включённых уведомлений. `LANILOT_PUBLIC_URL` (публичный HTTPS origin) добавляет кнопку перехода в карточку `/?load=...`. Без публичного адреса уведомление содержит ID и маршрут.

Дедупликация по компании, чату, режиму и снимку груза/экономики сохраняется при перезапуске. Изменившийся груз может дать новое уведомление. Перед запросом отправки сохраняется pending-запись; неподтверждённая доставка не повторяется автоматически, поскольку Telegram мог уже принять сообщение. Pending после аварии также блокирует повтор. Журнал показывает до 30 последних записей. API: `PUT /api/telegram`, `POST /api/telegram/check`, `/test`, `/run`; настройки и журнал доступны в `/api/state.telegram`. Сторонние токены не следует передавать в сообщения чата с разработчиком — вводите их непосредственно в форму приложения.

Seed создаёт выключенный демо-бот и учебное уведомление текущей компании, без реального токена. Демо-тест и демо-анализ пишут только в журнал; демо-анализ — детерминированный фильтр, **не ИИ**. Нормальный старт не сбрасывает пользовательские настройки, токен или историю.

### Текущий режим разработки: только фронтенд

Telegram в интерфейсе использует `TelegramMock`: настройки, тест и анализ работают в памяти браузера, без вызовов Telegram/OpenAI и без записи настроек через API. Поле токена отключено, доступен только демо-режим. После перезагрузки или ухода из раздела макет сбрасывается к seed. Серверный worker уведомлений остановлен. Ранее подготовленный backend сохранён для будущего этапа подключения.

### Фронтенд ИИ-помощника

Раздел «ИИ-помощник» — локальная демонстрация без запросов к ИИ и без нового серверного API. Три seed-диалога показывают поиск из Chicago, Reefer по RPM/DH и пустую выдачу с высоким порогом прибыли. Поддерживаются явно распознаваемые город отправления/назначения (из/from, в/to), техника, минимальные прибыль/RPM и максимальный DH. Ответ всегда показывает фактически применённые критерии; неподдерживаемые условия игнорируются с предупреждением. Условия можно изменить вручную через дропдауны с поиском и числовые поля. Расходы берутся из текущих настроек, варианты сортируются по расчётной прибыли. Карточка открывается поверх помощника, без потери диалога. История хранится только в localStorage: до 20 запросов/диалогов и 40 сообщений в каждом; повторный вход сохраняет пользовательские диалоги вместо повторного seed. На мобильном история скрыта по умолчанию и открывается кнопкой.

### Краткий интерфейс

Пояснения на рабочих экранах сокращены: убраны повторные описания страниц, технические примечания и дублирующие предупреждения о демо. Названия полей, показатели, статусы, ошибки и существенные последствия подтверждаемых действий сохранены. Инструкция Telegram и пример расчёта в настройках раскрываются по запросу. Подробности реализации остаются в этой документации и разделе справки.

### Сайдбар навигации

Все разделы перенесены из верхней полосы в левое меню: «Главная», «Диспетчерская», «Компания», помощь и профиль. Активный пункт и счётчики предложений/сообщений сохранены. На desktop сайдбар сворачивается до иконок; состояние сохраняется в localStorage. Длинное меню прокручивается внутри доступной высоты. При ширине до 900 px меню открывается кнопкой поверх страницы, блокирует фон и прокрутку, закрывается по Escape, крестику, фону или выбору раздела. Поддерживаются управление с клавиатуры и возврат фокуса. На desktop сайдбар находится в grid со sticky-позиционированием без GPU-трансформации; верхняя навигационная полоса удалена.

### Единое окно фильтров грузов

Над Load Board остаются количество грузов, иконка фильтров с числом активных условий и управление колонками. Маршрут, техника, дата, текстовый поиск, RPM, DH, источник, избранное, факторинг и сортировка собраны в одном модальном окне. Значения редактируются как черновик; список меняется только по «Применить». «Сбросить» очищает черновик, закрытие по крестику/Escape/фону отменяет несохранённые изменения. Внизу показано число совпадений до применения. На мобильном тело окна прокручивается, заголовок и действия остаются видимыми. Фон блокируется, фокус возвращается на кнопку фильтров.

### Виды Load Board

Переключатель «Таблица / Карточки» меняет представление общей выборки: фильтры, сортировка, избранное и пагинация сохраняются. Карточки открывают тот же боковой просмотр груза. Выбранный вид запоминается в браузере; при первом открытии на телефоне используются карточки, на компьютере — таблица. Оба вида заполнены существующими демо-грузами.

### Прибыль и настройки расходов

Параметры расчёта редактируются в «Настройки → Калькулятор прибыли» и сохраняются для новых расчётов. Карточка груза показывает ставку объявления без редактирования и прибыль по текущим настройкам расходов. Ссылки «Как рассчитано» и подчёркнутые значения прибыли открывают расшифровку: исходный пробег с DH, формулы топлива, оплаты водителя и факторинга, дороги, прочие расходы и итог. Предложения используют сохранённые расходы, финансовый учёт — суммы соответствующего рейса. Существующие демо-грузы, предложения и финансы доступны сразу; данные не сбрасываются.

### Графики на главной

Обзор содержит интерактивный график выручки и расчётной прибыли, кольцевую диаграмму статусов и рейтинг городов доставки. Переключатель периода охватывает текущую неделю или четыре недели до её конца. Экономика группируется по дате погрузки и использует ставки и сохранённые расходы предложений; отменённые рейсы исключены из денежных итогов. Подсказки доступны мышью, касанием и клавиатурой. Начальные данные — существующие демо-рейсы, дополнительные фиктивные показатели не генерируются.

### Скрытая презентация /pitch

`/pitch` открывает отдельную презентацию из 10 слайдов без ссылки в навигации кабинета. Добавлен `noindex, nofollow`; это скрытие из меню, а не защита доступа. GSAP анимирует появление содержимого, графики и обложку; при reduced motion анимации отключены. Есть навигация по слайдам и клавиатурой, пример экономики груза и интерактивная модель экономии времени с явными допущениями. Экраны продукта используют локальные демо-снимки; внешние API не нужны.

Кнопки PDF и HTML создают статичную презентацию в браузере. PDF содержит 10 страниц 16:9 и формируется в отдельном контейнере с фиксированным размером, поэтому мобильный экран не меняет раскладку. HTML включает изображения и стили, работает без приложения и JavaScript. Генераторы экспорта загружаются только при скачивании PDF. Готовые проверенные файлы также находятся в `output/`.

### Полноэкранный ИИ-помощник

Пункт «ИИ-помощник» открывает отдельный чат поверх всего кабинета, включая основную навигацию. Светлая область диалога, история слева и строка ввода оформлены в стиле привычных ИИ-чатов. «Назад» или Escape закрывают помощника и возвращают к прежней странице без сброса её фильтров. Диалог и черновик сохраняются при таком возврате; история также хранится локально. На телефоне история открывается отдельной выдвижной панелью. Демо-подбор, критерии с поиском и открытие груза поверх чата сохранены.

У полноэкранного помощника есть меню диалогов: переименование, закрепление, архив и удаление с подтверждением; поиск учитывает названия и текст запросов. Пустая история после удаления не заменяется seed-данными. В ответах доступны копирование, локальная оценка и повтор подбора; редактирование запроса пересоздаёт ветку после него. Enter отправляет, Shift+Enter добавляет строку. История скачивается в TXT. Вложения до 25 МБ (до 10 за сообщение) сохраняются локально в IndexedDB и открываются в просмотрщике; анализ вложений ИИ не подключён. Все эти действия остаются в демо-фронтенде и не отправляются во внешние сервисы.

### Skeleton loading

Общая задержка — `SKELETON_DELAY_MS = 3000` в `src/loading-config.js`. Скелетоны используются при запуске, навигации, смене списков/видов/периодов, открытии карточек, вкладок и диалогов, истории ИИ-чата, форм, карт, PDF, вложений и вариантов дропдауна. Они остаются до завершения настоящей загрузки, если она длится дольше. Контент остаётся смонтированным, но скрыт и inert на время загрузки; закрытие окна и навигация доступны. Таймеры отменяются при переключении и размонтировании, ошибки не проглатываются. Системная настройка reduced motion отключает мерцание. Демо-данные используются существующие, seed не сбрасывается.
